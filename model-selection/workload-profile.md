## Workload dimensions

**Critical** means failure materially breaks a scoped design/behavior obligation or invalidates its verification. **Secondary** means supporting quality or depth whose exact form is not prescribed. Secondary does not make an explicit TF obligation optional. Each dimension separates those priorities; they are not numerical weights or benchmark scores.

### W-01 — Repository-scale reasoning and long-horizon implementation

**Required work:** Build a coherent implementation plan across hero/loader, facts, stories/video, topic scenery, venue, FAQs, navigation, CTA shell and footer. Track shared dependencies: font/content height changes affect section offsets, story travel, reveal thresholds and video mapping; overlay state affects scroll locks, focus and navigation. Implement and revise these systems without losing previously established contracts or accepting one component's success as whole-page completion.

**Evidence:** SCOPE TF-01..06; BASELINES component/state crosswalk; V2 SR-01..39 and AC2-01..14 with current exclusions; MOTION M-01/M-05..12. READINESS enumerates the major states and coupled mechanics.

**Failure consequence:** Locally plausible sections can form an incoherent page: incorrect measured travel, stale active chapters, broken returns or regressions after typography changes.

**Priority:** Critical for complete scoped coverage, dependency reasoning and sustained correction. Secondary for the particular planning method or component decomposition. Large backend refactoring and distributed-system reasoning are not evidenced workloads here.

### W-02 — Evidence adherence and source-of-truth navigation

**Required work:** Resolve contract -> coverage row -> evidence -> acceptance seed; choose the right source/version/state, read final CSS rules and distinguish observations, declarations, inference and unknowns. Apply FAQ/topic corrections, distinguish R-* from SR-* and treat public source/media as inspection evidence until reuse is authorized. Preserve frozen originals and gates.

**Evidence:** ENTRY precedence; CORRECTIONS COR-01..03; BASELINES; SCOPE TR-01/TX-01/TU-01; V2 SR-40..46; SKILL invariants and separate gates. [Public-artifact report](../reference/haunted-boulder-city-v2/rev-2.0.0-real-01/public-artifacts.md) bounds source/version claims.

**Failure consequence:** A model can faithfully implement the wrong FAQ state, bind the wrong scenery, reproduce a transient blank menu or treat unavailable commerce as a current build blocker. Unauthorized source copying or evidence mutation invalidates the process.

**Priority:** Critical throughout. Secondary for exhaustive inspection of unrelated archived tooling once the authoritative locators answer the question. Evidence quantity is not a substitute for correct authority.

### W-03 — Advanced frontend implementation

**Required work:** Independently author responsive grids, sticky scene stages, clipped/overscanned imagery, scrims, outlined type, masks, filters, SVG/icon roles and independent layer transforms. Coordinate measurement, requestAnimationFrame, observers, animated disclosures, media readiness and fallbacks with DOM semantics. Preserve role-specific styling rather than applying generic component-library defaults.

**Evidence:** TYPE-ASSETS geometry/crops/type roles; MOTION M-02/M-04..11; SCOPE TF-01..04/TR-01. [Non-DOM report](../reference/haunted-boulder-city-v2/rev-2.0.0-real-01/non-dom-rendering.md) identifies CSS fog/noise, SVG, scrubbed video and source-declared detached canvas text measurement.

**Failure consequence:** Conventional cards, a uniform heading scale or generic gradient backgrounds erase the reference's composition; careless observer/animation integration breaks state and layout.

**Priority:** Critical for observable rendering and lifecycle behavior. Exact library choice and equivalent internal mechanisms are secondary. There is no mandated framework, WebGL/shader engine, worker/WASM subsystem or backend stack; detached canvas measurement does not make this a canvas-rendered application.

### W-04 — Visual/reference fidelity and typography

**Required work:** Inspect reference pixels alongside measurements and source roles; reproduce hierarchy, density, spacing, rhythm, crop/focal visibility, contrast and layer order in named revealed states. Preserve explicit line breaks and role-specific type metrics. Recalculate the hero title fit after font/load/resize changes. For actual authorized replacements, measure wraps, line boxes, overflow and crop/motion consequences rather than equating a family name or image subject with fidelity.

**Evidence:** SCOPE TF-01/02/TR-01; TYPE-ASSETS; BASELINES; E2-013/E2-014; V1 E-055 rendered fonts, E-064 media readiness and E-070 section pixels, linked through the evidence index. READINESS IP-M01/IP-M03 bound tolerance and replacement issues.

**Failure consequence:** Small type/crop errors propagate into section geometry and scroll mechanics; a visually attractive page can still be an inaccurate reconstruction. A self-generated baseline can hide the drift.

**Priority:** Critical. Pixel-identical random ambient phases, provider interiors and universal historical/current raster equality are outside scope. Numerical raster/geometry tolerances require later calibration; none are invented here.

### W-05 — Responsive behavior and breakpoint reasoning

**Required work:** Derive inclusive width rules and fluid relationships from the actual cascade. Test 759/760/761, 1099/1100/1101 and 1799/1800/1801; preserve narrow versus wide story topology, secondary grids and large-screen changes. Account for 1024x768, 768x1024, 844x390 landscape and 1440x400 short height. Separate viewport width, client width/scrollbar, height and input capability; 768 portrait still uses desktop stories, while minimum heights may exceed a short viewport.

**Evidence:** SCOPE TF-03; TYPE-ASSETS geometry section; V2 SR-35/36 and environment matrix; V1 E-040/E-041; MOTION M-04/M-06/M-12 and AC2-14.

**Failure consequence:** Device-name assumptions or a generic mobile breakpoint produce the wrong pinned/stacked structure, overflowing headings, clipped content or incorrect scroll dwell/seek geometry.

**Priority:** Critical for recorded Chromium conditions and inspected boundaries. Physical devices, other engines, zoom/AT, DPR2+, dark mode and RTL are uninspected TU-01 domains, not additional required parity branches.

### W-06 — Motion and interaction reconstruction

**Required work:** Preserve trigger, ordering, timing/easing relationships, entrance/exit phases, interruption and rearm behavior. Reconstruct loader/hero coordination, menu stagger and delayed hide cancellation, facts glyph decode with stable widths/readable twins, reveal reset, topic crossfade/meter cooldown, ambient fog/marquee/marks, pointer flashlight and CTA spirit character. Assess multiple phases and ranges instead of copying one random frame.

**Evidence:** SCOPE TF-04/06; MOTION M-01..12; V1 E-060/E-062/E-080/E-085; BASELINES repaired menu and temporal-state distinctions; AC2-03/04/06/09 under current scope.

**Failure consequence:** Correct endpoints can conceal abrupt transitions, invisible staggered children, repeated unintended triggers or overlays hidden by an old close timer after reopening. Removing distinctive motion changes the requested experience.

**Priority:** Critical for specified character and state relationships, including layered ambient effects. Exact random glyph/flight/fog phase identity is not required; source-declared distributions are not exhaustively observed timing results. Capture deadlines measured from navigation are not transition durations.

### W-07 — Scroll-driven and stateful behavior

**Required work:** Implement the wide story pin/track using measured travel, hold regions, smoothstep progress, counter-moving scenery, count/active state and crossing fog; reverse correctly. Map scroll to UFO seek with lazy source selection, one seek in flight and still fallback. Select highlights by row position with exact topic-image bindings. Preserve reveal/full-exit reset and facts rearm, interruptible in-page scroll, native keyboard/touch/nested scroll relationships, fragment history/focus and root reset. Manage FAQ intent versus transient native state and modal/menu close/reopen state.

**Evidence:** MOTION M-05..11; COR-01/COR-03; V2 SR-03..07/13..23/29/31/39; V1 E-050/E-080; SCOPE TF-04/06; corrected AC2-03/05/07/09/11. Fresh-normal UFO samples progress and reverse; a static end frame does not establish scrubbing.

**Failure consequence:** One-way demos fail reverse navigation; stale handlers corrupt active chapters or FAQ intent; guessed absolute offsets break after resize/content changes. A simple slideshow does not preserve the scroll-controlled narrative.

**Priority:** Critical. Preserve the host shell's mounted-state/return character where applicable; actual replacement action persistence and loading/error/success semantics depend on TA-01. Eventbrite selection, inventory, purchase/payment and backend behavior are excluded.

### W-08 — Browser, tool and MCP usage

**Required work:** The model/harness must read/search files and structured evidence, inspect images, edit scoped code, run local checks and drive an actual browser for target comparisons. Discover supported schemas, verify page/context IDs and viewport/input conditions, exercise trusted click/keyboard/scroll actions, inspect styles/geometry/AX/media state, and save usable screenshots/traces/results. Diagnose adapter/root/readiness failures and use a justified equivalent capability without changing user profiles or security settings.

**Evidence:** V1 tool decisions G-01..09; V2 environment matrix and [tool-capability record](../reference/haunted-boulder-city-v2/rev-2.0.0-real-01/observations/tool-capabilities.json); V2 handoff; [skill tool routing](../skills/reference-reconstruction/references/tool-selection.md). Existing evidence shows Chrome MCP unavailable in one session, Polypane schema/save-root limits and an isolated maintained runner used for specific gaps.

**Failure consequence:** Tool availability can be mistaken for browser access; stale UIDs or wrong emulation yield false conclusions, and failed saves leave no replayable proof. Text-only code generation cannot substantiate visual or temporal fidelity.

**Priority:** Critical at the model/harness level for browser and visual feedback. A particular MCP product, Figma integration, extra plugin installation or fresh reference recapture is secondary/not inherently required. Historical tool failures are evidence of recovery needs, not claims about today's tool availability. This profile preparation requires no live browsing.

### W-09 — Debugging and verification discipline

**Required work:** Reproduce mismatches in controlled fresh/reset contexts; distinguish environment/capture errors, implementation defects, evidence gaps and intentional adaptations. Use bounded font/loader/visible-media readiness plus named descendant opacity/filter/transform/text assertions and geometric convergence. Check static appearance separately from temporal behavior, reverse/interrupted actions, keyboard/history and preference/input branches. Inspect actual/diff/overlay/trace artifacts, fix the cause and rerun affected cases without updating baselines or thresholds to hide drift.

**Evidence:** ENTRY comparison recipe; E2-013 canonical repairs; V2 AC2 seeds; SKILL implementation handoff/acceptance template and [settled-appearance rules](../skills/reference-reconstruction/references/settled-appearance.md); READINESS limits. V1 G-03 records an unbounded lazy-image wait failure; V2 repairs show geometry stability alone missing child/provider readiness.

**Failure consequence:** A running page, passing file hashes or stable parent rectangle can be falsely accepted while content remains invisible. Disabling animation for screenshots cannot verify motion; a simulated outage cannot prove a natural failure state.

**Priority:** Critical for valid acceptance. Exact test-runner organization is secondary. Reference capture runs and the pre-build PASS are not executed target tests; overall fidelity claims must remain limited to tested cases and environments.

### W-10 — Long-context handling and durable continuity

**Required work:** Retrieve relevant artifacts rather than flattening the repository into one prompt. Retain scope exclusions, corrected claims, source IDs, environments, state recipes, unresolved choices and verified implementation status across implementation/debugging cycles. Re-enter from the packet and durable records without relying on chat history; keep historical and current claims distinct when reviewing later changes.

**Evidence:** SKILL's inspectable-without-chat invariant and handoff; ENTRY compact locators; BASELINES crosswalk/index; CORRECTIONS/anchor audit; V2 SR-46 portable package/handoff; READINESS cold-start evaluation.

**Failure consequence:** Context loss resurrects multi-open FAQ prose, wrong baselines or excluded commerce requirements, or drops an entire reduced/touch/reversal branch after a later fix.

**Priority:** Critical for reliable retrieval and cross-turn consistency. A particular raw context-window size, memory system or multi-agent architecture is not established. Evaluate usable continuity under the chosen harness rather than inferring it from advertised token capacity.

### W-11 — Accessibility, reduced-motion and touch branches

**Required work:** Preserve semantic regions, heading/image/control names, native keyboard activation, expanded/inert state, skip/navigation focus, menu cycling and Escape/close return relationships. Document target corrections to reference defects, including dialog Tab escape, with their visual/interaction consequences. Implement fresh reduced entry with visible static reveals, vertical stories, UFO still/no assigned clip and suppressed flashlight/glitch/spirit; distinguish it from preference changes in an existing session. Separate fine pointer from touch/coarse/hover-none behavior, including glow cancellation, native scrolling, touch hero fallback and scroll-triggered topic/CTA effects.

**Evidence:** SCOPE TF-05/TF-03; MOTION M-04/M-05/M-07..12; V2 SR-06/11..23/29/30/35/36; V1 E-041/E-056/E-080/E-090; READINESS IP-M02 retains the incomplete mid-decode preference-change timeline.

**Failure consequence:** A visually correct interface can be inaccessible, leave closed answers focusable, trap/lose focus or run unwanted motion. Treating fresh reduced and switched sessions as identical misrepresents documented video/observer history.

**Priority:** Critical for scoped operability and preference/input relationships. Reference defects are facts to address through explicit target deviations, not requirements to reproduce. Actual assistive-technology/device parity and complete mid-decode change behavior remain unverified; no broad certification is implied.

### W-12 — Avoid destructive simplification

**Required work:** Preserve complexity that serves the contract while independently choosing implementation structure. Do not replace pinned stories with a generic carousel, scrubbed media with autoplay, single-intent interruptible FAQ with independent instant toggles, layered scenes with generic gradients or measured type with arbitrary shrinking. Do not hide overflow, omit sections, truncate meaningful content or freeze ambient motion solely to pass a screenshot. Respect sanctioned narrow/reduced simplifications and approved substitutions as explicit branches/deviations.

**Evidence:** SCOPE TF-01..06/TA-01/TR-01; MOTION; TYPE-ASSETS; SKILL implementation handoff explicitly rejects shrinking/hiding/flattening shortcuts; BASELINES rejects full-page-only acceptance.

**Failure consequence:** Superficial resemblance can pass one screenshot while losing the narrative, interaction graph, content or responsive experience the project actually requests.

**Priority:** Critical as a cross-cutting fidelity constraint. Internal refactoring and simpler equivalent mechanisms are acceptable; reproducing reference code structure is not an obligation. Excluded commerce must not be rebuilt in the name of completeness.

### W-13 — Implementation quality, maintainability and adaptation

**Required work:** Keep layout measurement, rendering and interaction state coherent as dimensions/content change; prevent stale animation completion and delayed-hide callbacks from overriding current intent. Avoid unnecessary concurrent frame/seek work and preserve offscreen/document-hidden ambient lifecycle behavior. Make reference-equivalent fixtures and later target mappings distinguishable, with role-specific metrics, topic bindings and motion parameters traceable to evidence. Support approved long/short/empty/many-item stress fixtures without silently changing design rules.

**Evidence:** MOTION M-02/M-04/M-06/M-07/M-09..11 (visibility pauses, RAF coalescing, seek serialization, generation/cancellation and resize handling); SCOPE TA-01/TR-01; SKILL handoff and acceptance records; TYPE-ASSETS substitution consequences.

**Failure consequence:** Race conditions make repeat/reverse actions unreliable; hardcoded historical offsets or fixture-specific styling break after adaptation. Opaque parameter changes make fidelity regressions difficult to diagnose.

**Priority:** Critical for lifecycle correctness, repeatability and maintainable adaptation boundaries. Particular abstractions, lint rules, framework, coverage percentages, performance budgets or production deployment practices are not specified; stylistic polish beyond those needs is secondary. No enterprise/backend architecture requirement follows from this frontend workload.
